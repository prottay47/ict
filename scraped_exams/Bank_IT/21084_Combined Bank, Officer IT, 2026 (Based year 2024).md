Object Oriented Programming

Explain the concepts of Inheritance and Polymorphism in Java. Write a Java program to demonstrate method overriding.

**Inheritance**

**Inheritance**  is an Object-Oriented Programming (OOP) feature in which one class (child/subclass) acquires the properties and methods of another class (parent/superclass). It promotes  **Code Reusability** ,  **Extensibility** , and easier maintenance.

**Polymorphism**

**Polymorphism**  means "many forms." It allows the same method to perform different behaviors depending on the object that invokes it. In Java,  **Method Overriding**  is an example of  **Runtime Polymorphism** .

**Java Program: Demonstration of Method Overriding**

```
class Animal {
void sound() {
System.out.println("Animal makes a sound");
}
}

class Dog extends Animal {
@Override
void sound() {
System.out.println("Dog barks");
}
}

public class Main {
public static void main(String[] args) {
Animal obj = new Dog();
obj.sound();
}
}
```

**Output**

```
Dog barks
```

**Explanation**

The  **Dog**  class inherits the  **Animal**  class and overrides the  **sound()**  method. At runtime, the overridden method of the  **Dog**  class is executed, demonstrating  **Method Overriding**  and  **Runtime Polymorphism** .

What is JDBC? Explain the steps required to connect a Java application to a MySQL database.

**JDBC (Java Database Connectivity)**

**JDBC (Java Database Connectivity)**  is a standard Java API that enables Java applications to connect to relational databases such as  **MySQL** ,  **Oracle** ,  **SQL Server** , and  **PostgreSQL** . It allows applications to execute SQL queries, retrieve data, and update database records.

**Steps to Connect a Java Application to a MySQL Database**

**Add the MySQL JDBC Driver**
Include the  **MySQL Connector/J**  library (JAR file) in the Java project.
**Import JDBC Packages**
Import the required package:

```
import java.sql.*;
```

**Load the JDBC Driver**
Load the MySQL JDBC driver.

```
Class.forName("com.mysql.cj.jdbc.Driver");
```

**Establish the Database Connection**
Create a connection using the database URL, username, and password.

```
Connection con = DriverManager.getConnection(
"jdbc:mysql://localhost:3306/mydb",
"root",
"password");
```

**Create a Statement**
Create a  **Statement**  or  **PreparedStatement**  object.

```
Statement stmt = con.createStatement();
```

**Execute SQL Queries**
Execute SQL commands using the statement object.

```
ResultSet rs = stmt.executeQuery("SELECT * FROM student");
```

**Process the Result**
Read data from the  **ResultSet** .

```
while(rs.next()){
System.out.println(rs.getInt("id") + " " +
rs.getString("name"));
}
```

**Close Resources**
Close the  **ResultSet** ,  **Statement** , and  **Connection**  objects.

```
rs.close();
stmt.close();
con.close();
```

**Conclusion**

JDBC provides a standard way for Java applications to communicate with MySQL databases through the steps:  **Load Driver → Connect → Create Statement → Execute SQL → Process Result → Close Connection** .

Describe the SQL Injection and Cross-Site Scripting (XSS) web security threats and suggest preventive measures for each.

**SQL Injection (SQLi) and Cross-Site Scripting (XSS)**
**1. SQL Injection (SQLi)**

**SQL Injection**  is a web security vulnerability in which an attacker inserts malicious  **SQL**  statements into user input fields. If the application does not properly validate the input, the attacker can execute unauthorized database queries to read, modify, or delete data.

**Preventive Measures**

• Use  **Prepared Statements (Parameterized Queries)** .
• Validate and sanitize all user inputs.
• Apply the  **Principle of Least Privilege**  for database accounts.
• Avoid constructing SQL queries using string concatenation.

**2. Cross-Site Scripting (XSS)**

**Cross-Site Scripting (XSS)**  is a vulnerability in which an attacker injects malicious  **JavaScript**  or other client-side scripts into a trusted web page. When another user visits the page, the malicious script executes in the user's browser.

**Preventive Measures**

• Validate and sanitize user input.
• Encode HTML output before displaying user-supplied data.
• Use a  **Content Security Policy (CSP)** .
• Store sensitive cookies with the  **HttpOnly**  and  **Secure**  attributes.

**Conclusion**

**SQL Injection**  targets the  **Database** , whereas  **XSS**  targets the  **User's Browser** . Proper input validation, output encoding, and secure coding practices are essential to prevent both attacks.



**SQL Injection (SQLi) এবং Cross-Site Scripting (XSS)**
**১. SQL Injection (SQLi)**

**SQL Injection**  হলো একটি Web Security Vulnerability, যেখানে আক্রমণকারী User Input-এর মাধ্যমে ক্ষতিকর  **SQL**  Query প্রবেশ করায়। যদি Application Input সঠিকভাবে Validate না করে, তাহলে আক্রমণকারী Database-এর Data পড়তে, পরিবর্তন করতে বা মুছে ফেলতে পারে।

**প্রতিরোধের উপায়**

•  **Prepared Statement (Parameterized Query)**  ব্যবহার করতে হবে।
• সকল User Input  **Validate**  এবং  **Sanitize**  করতে হবে।
• Database Account-এ  **Least Privilege**  নীতি অনুসরণ করতে হবে।
• String Concatenation ব্যবহার করে SQL Query তৈরি করা যাবে না।

**২. Cross-Site Scripting (XSS)**

**Cross-Site Scripting (XSS)**  হলো এমন একটি Vulnerability, যেখানে আক্রমণকারী ক্ষতিকর  **JavaScript**  বা অন্যান্য Client-side Script Web Page-এ Inject করে। অন্য কোনো User সেই Page Visit করলে Browser-এ ওই Script Execute হয়।

**প্রতিরোধের উপায়**

• সকল User Input  **Validate**  এবং  **Sanitize**  করতে হবে।
• User-এর Data প্রদর্শনের আগে  **HTML Output Encoding**  করতে হবে।
•  **Content Security Policy (CSP)**  ব্যবহার করতে হবে।
• Cookie-তে  **HttpOnly**  এবং  **Secure**  Attribute ব্যবহার করতে হবে।

**উপসংহার**

**SQL Injection**  মূলত  **Database** -কে লক্ষ্য করে, আর  **XSS**  ব্যবহারকারীর  **Browser** -কে লক্ষ্য করে। সঠিক  **Input Validation** ,  **Output Encoding**  এবং Secure Coding Practice অনুসরণ করলে এই দুই ধরনের আক্রমণ প্রতিরোধ করা যায়।

What is the difference between a Multiplexer and a Demultiplexer? Explain one practical application of each in digital systems.

**Difference Between Multiplexer (MUX) and Demultiplexer (DEMUX)**

Multiplexer (MUX)
Demultiplexer (DEMUX)

A  **Multiplexer (MUX)**  is a digital circuit that selects one input from multiple input lines and forwards it to a single output line.
A  **Demultiplexer (DEMUX)**  is a digital circuit that receives data from one input line and routes it to one of multiple output lines.

Many Inputs → One Output.
One Input → Many Outputs.

Uses  **Select Lines**  to choose one input.
Uses  **Select Lines**  to choose the destination output.

Acts as a  **Data Selector** .
Acts as a  **Data Distributor** .

Reduces the number of communication lines.
Distributes data to different devices or destinations.

**Practical Applications**
**Multiplexer (MUX):**  Used in  **Communication Systems**  to transmit multiple signals over a single communication channel, reducing wiring and transmission cost.
**Demultiplexer (DEMUX):**  Used at the receiving end of  **Communication Systems**  to separate the received data and deliver it to the correct output device or destination.
**Conclusion**
A  **Multiplexer**  combines multiple input signals into one output, whereas a  **Demultiplexer**  distributes one input signal to one of many outputs. They are widely used together in digital communication and data transmission systems.

**Multiplexer (MUX) এবং Demultiplexer (DEMUX)-এর মধ্যে পার্থক্য**

Multiplexer (MUX)
Demultiplexer (DEMUX)

**Demultiplexer (DEMUX)**  হলো একটি Digital Circuit, যা একটি Input Line-এর Data-কে একাধিক Output Line-এর মধ্যে নির্দিষ্ট একটি Output-এ পাঠায়।

Network Topology & Devices

Describe the functions of a Switch and a Router and explain two key differences between these networking devices.

**Switch and Router**
**Functions of a Switch**

A  **Switch**  is a networking device that connects multiple devices within the same  **Local Area Network (LAN)** . It forwards data frames to the correct destination using  **MAC Addresses** , improving network efficiency and reducing unnecessary traffic.

**Functions of a Router**

A  **Router**  is a networking device that connects two or more different networks, such as a  **LAN**  and the  **Internet** . It forwards data packets between networks using  **IP Addresses**  and determines the best path for packet delivery.

**Key Differences Between Switch and Router**

Switch
Router

Operates mainly at the  **Data Link Layer (Layer 2)**  of the OSI model.
Operates at the  **Network Layer (Layer 3)**  of the OSI model.

Uses  **MAC Addresses**  to forward data within the same network.
Uses  **IP Addresses**  to route packets between different networks.

A software company has been hired to develop an Online Library Management System for a university. The librarian wants the system to be delivered in phases so that feedback from users can be incorporated after each release. As a software developer, identify the most suitable Software Development Life Cycle (SDLC) model for this project. Justify your choice by mentioning two advantages of the selected model.

**Suitable SDLC Model for the Online Library Management System**

The most suitable  **Software Development Life Cycle (SDLC)**  model for this project is the  **Incremental Model** .

**Justification**

The university librarian wants the system to be delivered in  **phases** , allowing users to provide feedback after each release. The  **Incremental Model**  develops and delivers the software in multiple increments, enabling improvements based on user feedback before the next release.

**Advantages of the Incremental Model**

**1. Early Delivery of Software:**
The system is delivered in small functional releases, allowing users to start using important features earlier.

**2. Easy Incorporation of User Feedback:**
Feedback received after each release can be incorporated into subsequent increments, resulting in a system that better meets user requirements.

**Conclusion**

The  **Incremental Model**  is the best choice because it supports phased delivery, continuous user feedback, and gradual enhancement of the Online Library Management System.



**Online Library Management System-এর জন্য উপযুক্ত SDLC Model**

এই Project-এর জন্য সবচেয়ে উপযুক্ত  **Software Development Life Cycle (SDLC)**  Model হলো  **Incremental Model** ।

সম্পূর্ণ Project শেষ হওয়ার অপেক্ষা না করে গুরুত্বপূর্ণ Feature-গুলো ধাপে ধাপে ব্যবহারকারীর কাছে সরবরাহ করা যায়।
